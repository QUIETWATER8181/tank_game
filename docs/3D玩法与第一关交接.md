# 第一关、战斗机制、拼装手感与界面交接

> 记录时间：2026-11-14。适用对象：接手「把 3D 车间从可搭建的模型预览，变成能真正开起来打的第一关」的开发者。
> 本文只写**现状、规格、改法和验收**，不改代码。配套文档：[3D 坦克模型精致化交接](3D坦克模型精致化交接.md)（模型层）、[新模式架构](新模式架构.md)（数据层）。
> 上一轮已完成 M1/M2（模型精致化），提交 `8ee77c8`，已推送到 `origin/main`。

## 0. 一分钟结论

- **现在能做什么**：`mode3d.html` 有 4 个页签——车间（装部件/拖动/评估/制造）、模型仓库（GLB 入库）、坦克仓库、第一关。第一关是一段 **24 × 180 米的静态走廊布景**，玩家坦克和 4 辆敌坦都只是摆件，`模拟消灭` 按钮直接向规则状态机发事件。
- **缺什么**：没有操控、没有弹道、没有 AI、没有伤害结算、没有相机跟随；拼装是「拖到哪算哪 + 松手整棵模型重建」；界面首屏有 4 个页签 + 6 个镜头按钮 + 画质下拉 + 左侧 10 段表单 + 右侧 12 项数值 + 底部 10 个按钮，新手第一眼不知道从哪下手。
- **这一轮的目标**：**让第一关真的能开、能打、能赢**；把拼装从「能用」做到「顺手」；把界面从「开发者面板」收到「三步就能玩」。
- **最关键的三个决定**：
  1. 战斗层放在 `js/three/combat.mjs`（新文件），只做表现与实时模拟；**胜负判定仍然只走 `js/mode/campaign.mjs` 的 `transitionRun`**，数据层不动。
  2. 第一关保持 180 米纵深，但把「一条直路」改成「三段式」：接敌 → 侧翼选择 → 基地攻坚；宽度 24 → 36 米。
  3. 拼装手感的根因不是样式，是**松手时整棵模型重建 + 拖动中按 0.1 m 跳格**。先改这两点，再加吸附预览。

### 1.2 当前流程（实测走一遍）

```
打开 mode3d.html
 → 默认在「01 车间」，左侧已有一份起始蓝图（5 个部件）
 → 点目录里的部件 → 自动 suggestPlacement 放到车体上 → 选中
 → 在 3D 里拖动 → 松手 applyDrag → moveCandidate 重新连接 → 整棵模型重建
 → 右侧评估通过 → 「制造并入库」→ 跳到「03 坦克仓库」
 → 「准备第一关」→ 跳到「04 第一关」，镜头缓动到玩家
 → 「开始规则测试」→ 手动点 4 次「模拟消灭」+ 1 次「模拟摧毁基地」→ 胜利
```

**关键事实**：整条链路上**没有任何一帧在跑战斗**。`level-scene.mjs` 的 `update(delta)` 只更新雷达旋转、旗帜波动、烟雾、尘埃；敌坦只有 ±0.04 rad 的待机摆动。

### 1.3 现有数据契约（不能破坏）

```js
// 关卡（js/mode/campaign.mjs）
FIRST_LEVEL = {
  id, name, nextLevelId,
  map: { generator: 'corridor-v1', width: 24, length: 180, forwardAxis: '+Z' },
  playerSpawn: [0, 0, 8],
  enemies: [{ id, templateId, position: [x,0,z], behavior, triggerZ }],
  base: { id, position: [0,0,170], maxHealth: 150 },
  victory: { allEnemiesDestroyed: true, baseDestroyed: true }
}

// 运行态
createRun(tank, level) -> { schemaVersion, status: 'ready'|'running'|'victory'|'defeat',
  tick, tank, level, defeatedEnemies: [], baseDestroyed, playerDestroyed }
transitionRun(state, event) // event: start | enemy-destroyed{id} | base-destroyed | player-destroyed

// 伤害
damageAfterDefense(raw, defense, { sameTeam, friendlyFire }) = raw * 100 / (100 + defense)
```

**结论**：战斗层只需要产出这 4 种事件，`run` 仍然是唯一的胜负来源。这样存档、探针、规则测试全部不用改。

## 2. 外部调研：可借鉴的开源项目与做法

> 说明：本次会话的联网检索接口鉴权失败（DeepSeek 搜索端点 401），只有部分公开文档能取到。**下文带链接的是查到原文的；标注「通行做法/推断」的是我从同类游戏的公开资料与工程经验推出来的，没有逐条跑过，落地前请再验一次。** 下一位接手时建议先用 `web_search` 补齐三个方向：`three.js BatchedMesh`、`WoT battle mechanics`、`building game placement UX`。

### 2.1 浏览器 3D 的工程做法

- **`InstancedMesh` / `BatchedMesh` / `LOD`**（[three.js 文档](https://threejs.org/docs/#api/en/objects/InstancedMesh)）：我们已经在用 `InstancedMesh`（石头/灌木/沙袋）和 `mergeGeometries`（坦克按材质合并）。`BatchedMesh` 能把「同材质、不同几何」合成一次绘制——**推断**：对「每辆 27 个 mesh」的战斗场景有 5–8 倍绘制下降，但它要求几何在创建时登记，和现在「松手重建整棵模型」的流程冲突，**建议留到 LOD 阶段**，本轮不要动。
- **按需渲染**：`runtime.mjs` 已经是 `dirty + invalidate` 模型。战斗一旦开始 `systems.size > 0` 会持续重绘，所以**战斗层的成本必须自己控**（弹丸池化、爆炸池化、每帧只做一次矩阵更新）。
- **固定步长**：`stepper.mjs` 已经是 60 Hz 固定步、最多追 5 步。**战斗模拟必须挂 `fixedUpdate`**，不能挂 `update(delta)`——否则 144 Hz 屏上炮弹飞得更快。这是当前 `level-scene` 用 `update(delta)` 的隐患。
- **资源释放**：[官方 cleanup 指南](https://threejs.org/manual/#en/cleanup) 明确要求 geometry/material/texture 各自 `dispose`。战斗层新增的弹丸、爆炸、残骸都挂在关卡根节点下，会被 `disposeObject(root)` 统一释放——**前提是不要跨根节点共享材质**。

### 2.2 坦克战斗机制（有出处的部分）

WoT 的官方 wiki 与社区逆向把「手感」拆成了可调参数，这套参数化方式比任何开源坦克小游戏都值得抄：

- **地形阻力是移速的总闸**（[WoT Battle Mechanics](https://wiki.wargaming.net/en/Battle_Mechanics)、[GuidesBlitz: terrain resistance](https://guidesblitz.com/terrain-resistance-ground-resistance/)）：地面分 hard / medium / soft 三档，阻力三元组典型值 `0.7/0.8/1.5`（好悬挂）、`1.0/1.2/2.2`（平均）、`1.2/1.4/2.5`（差）。牵引力按 `1 / R` 打折，**极速是变速箱上限，不是阻力上限**——软地上是「到不了极速」，而不是「被限速」。→ 我们的泥地/碎石区就按这个做：只改加速度与可达速度，不改 `stats.moveSpeed`。
- **车体转向也受阻力影响**（[GuidesBlitz: traverse speed](https://guidesblitz.com/traverse-speed-hull-turn-rate/)）：`traverse_on_X = traverse_hard × (R.hard / R[X])`。→ 泥地里转向变慢，是免费的「重」的手感。
- **各吨位的合理区间**（同一批资料的调参表，重型坦克一列）：比功率 10–15 hp/t、极速 30–40 km/h、车体转向 20–30°/s、炮塔转向 20–28°/s、俯仰 +15/−6°、精度 0.35–0.40 m@100 m、瞄准时间 2.5–3.2 s。→ 我们现在的 `turnSpeed 0.4–0.9 rad/s`（23–52°/s）和 `turretSpeed 0.6–1.2 rad/s`（34–69°/s）**明显比真实坦克快**，这是对的（街机化），但可以用来校验「重坦应该更慢」的相对关系。
- **散布与瞄准圈**：精度 = 基础精度 + 移动/转车体/转炮塔/开火四个扩散项，开火后有一个固定的 4× 扩散。→ 本轮**不做**散布（第一关 4 个目标，加散布只会让人打不中而不知道为什么），但把这个字段留在 `stats` 里，给以后的「精度改装」用。
- **相机两套**：街机是第三人称环绕（跟随车体），狙击镜是第一人称从炮口看。→ 我们只需要街机那套，且**必须跟车体而不是跟鼠标**，否则瞄准时画面会晃。

### 2.3 建造/组装类玩法的交互（通行做法，未逐条验证）

- **ghost 预览 + 松手提交**：Besiege / Scrap Mechanic / Kerbal 都是「拖动时半透明预览、松手才落位」，且非法位置用**颜色**而不是弹窗提示。
- **磁吸优先于网格**：积木类用纯网格；模块类（有语义的部件）用「自由拖动 + 就近吸附」。我们的炮塔必须坐在座圈上，属于后者。
- **撤销粒度 = 一次操作**：拖动开始压栈、吸附与重连并入同一次提交。
- **光标即状态**：`grab` / `grabbing` / `not-allowed` 三态，比文字提示快。

### 2.4 简洁 UI 与新手引导（通行做法）

- 常驻 HUD 只放「会死人的信息」：血量、弹药/装填、剩余目标。其余按需展开。
- 渐进披露：把「坐标 / 朝向 / 连接 / 外观 / 草稿」收进 `<details>`，首屏只留「装什么、长什么样、能不能造」。
- 三步就地引导（高亮一个元素 + 一句话），比弹窗教程有效；空状态直接给主按钮。

### 2.5 最值得抄的 8 条

1. 战斗用**运动学模型**（限速 + 加速度 + 差速转向），不上刚体物理。
2. 模拟挂 `fixedUpdate`（60 Hz），渲染插值。
3. 地形阻力只改**加速度与可达速度**，不改 `moveSpeed` 这个展示值。
4. 炮塔独立于车体，转速来自 `stats.turretSpeed`；相机跟车体。
5. 炮弹用**低角弹道解** `θ = ½·asin(g·d/v²)`，超出射程才抬到 45°。
6. 放置交互 = **自由拖动 + 松手磁吸 + ghost 预览 + 颜色表示合法性**。
7. HUD 只放 4 个数：血量、装填、剩余目标、基地血量。
8. 新手引导 = 三步就地高亮，不是弹窗教程。

## 3. 第一关场地设计

### 3.1 现在的问题

- **一条直路**：`ROAD_WIDTH 13`、`map.width 24`，敌人排在 z = 42 / 82 / 120 / 150 的正线上，玩家只能沿 +Z 推进。
- **没有高度差**：地面是一整块 `PlaneGeometry(560, 640)`，`y = -0.02`。没有坡、没有掩体高地。
- **掩体是装饰**：沙袋墙（z = 24/64/99/134）、路障、木箱全是 `InstancedMesh`，没有碰撞，也没有视线遮挡。
- **节奏平**：4 个触发线（25/65/100/135）只是让敌人「出现」，没有遭遇战设计。
- **基地是布景**：围墙 + 门楼 + 碉堡，但没有防守逻辑。

### 3.2 目标布局：三段式（宽度 24 → 36 米）

```
z=0                                                             z=180
│ 出生点  │  ① 接敌区   │   ② 侧翼区    │    ③ 基地攻坚    │
│  z 8    │  z 25–60    │   z 60–125    │   z 125–175      │
│         │  1 辆正面   │  2 辆侧翼     │  守卫 + 基地     │
└─────────┴─────────────┴───────────────┴──────────────────┘
   宽 36m      宽 24m         宽 36m            宽 36m
```

**① 接敌区（z 25–60）**
- 路面仍 13 m，两侧各留 5 m 土路。
- 中央 z=38 放一组**半埋残骸**（3 个可碰撞方块，高 1.2 m）——第一辆敌坦躲在后面，教玩家「先绕再打」。
- 两侧沙袋掩体（高 0.9 m，可碰撞），玩家可以贴上去只露炮塔。

**② 侧翼区（z 60–125）**
- z=95 横一道**土堤**（高 2.6 m，宽 36 m），中间留两个 6 m 缺口（x = ±6）。土堤挡住直线视线，逼玩家选左或右。
- 左缺口外是一片**泥地**（`resistance 2.2`，对应移速 ×0.45），但能绕到敌坦侧后。
- 右缺口外是**碎石坡**（`resistance 1.4`，移速 ×0.71），能获得 1.5 m 的射击高度优势。
- 阻力系数沿用 2.2 节的 WoT 三档：硬地 1.0 / 中地 1.2–1.4 / 软地 2.2，**只改加速度与可达速度**。
- 两辆侧翼敌坦分别守在缺口外 25 m 处。

**③ 基地攻坚（z 125–175）**
- 基地围墙保留，但**大门加宽到 12 m**，门前 15 m 是一片开阔地（无掩体）——冲门要付出代价。
- 基地内加两个**弹药堆**（打爆后 3 m 溅射，可连锁）。
- 守卫在门内侧，炮口朝门。

### 3.3 数据契约变更（保持向后兼容）

```js
// campaign.mjs —— 只增字段，不改已有字段语义
map: { generator: 'corridor-v2', width: 36, length: 180, forwardAxis: '+Z' }

// 新增（可选，缺省时场景按旧逻辑生成）
map.cover = [
  { id, kind: 'berm'|'sandbag'|'wreck'|'crate'|'rock', position: [x,y,z], size: [w,h,d], solid: true }
]
map.zones = [
  { id, kind: 'mud'|'rubble', position: [x,y,z], size: [w,d], speedFactor: 0.55 }
]
```

- `solid: true` 的掩体进入战斗碰撞列表（圆柱近似，半径 = `max(w,d)/2`）。
- `zones` 只影响移速，不影响弹道。
- **旧存档**（没有 `cover`/`zones`）必须仍能加载：`generateLevel()` 负责补齐默认值。

## 4. 战斗机制规格

> 实现位置建议：新增 `js/three/combat.mjs`，由 `level-scene.mjs` 在 `combat: true` 时装配。**`js/mode/` 一行不改**。

### 4.1 单位

```js
{
  id, team: 'player'|'enemy', object,          // 场景根节点
  turret, weapon, pivot,                        // 仅玩家保留部件组
  stats,                                        // 来自 evaluateTank().stats
  position: Vector3, yaw, turretYaw, pitch,
  health, reload, alive, speed, triggerZ, behavior
}
```

**玩家**必须用 `buildTankModel(blueprint, { merged: true })`（保留部件组），并把 `weapon` 通过 `pivot.attach(weapon)` 挂到炮塔内的俯仰枢轴上，否则转炮塔时炮管不跟随（见 3D 模型交接 7.3）。
**敌坦**继续 `whole: true`，整辆转向瞄准，省 16 次绘制/辆。

### 4.2 操控（运动学，不是物理）

```
throttle = W - S
steer    = A - D
R        = 当前脚下地形的阻力（硬地 1.0 / 泥地 2.2）
speed    = damp(speed, throttle * moveSpeed / R, throttle ? 2.6 : 3.4, dt)
grip     = clamp(|speed| / (moveSpeed * 0.4), 0, 1)
yaw     += steer * turnSpeed / R * sign(speed) * (0.45 + 0.55 * grip) * dt
position += (sin(yaw), 0, cos(yaw)) * speed * dt
```

- `damp(a, b, λ, dt) = a + (b - a) * (1 - e^(-λ·dt))`，避免生硬的线性加速。
- 低速时仍有 45% 转向能力（原地转向的近似），速度越快转向越有效。
- **不做**悬挂、坡度、翻车。

### 4.3 瞄准与炮塔

```
瞄准点 = 屏幕指针 → 相机射线 → 与 y=1.2 平面求交
目标角 = atan2(aim.x - tank.x, aim.z - tank.z)
炮塔角 += clamp(wrap(目标角 - 车体角 - 炮塔角), ±turretSpeed·dt)
```

- 无炮塔时（`stats.turretSpeed` 不存在）：车体直接转向目标角，转速用 `turnSpeed`。
- 炮管俯仰：`pitch` 由弹道解算给出，`damp` 到目标值（λ=8），限制 `[-0.06, 0.32] rad`。
- 炮塔枢轴用部件组自身 `rotation.y`，俯仰枢轴用新建 `Group`（局部 z ≈ 1.5 m，炮盾位置）。

### 4.4 弹道

低角解（水平距离 d、初速 v、重力 g、高差 h）：

```
θ = ½ · asin(g·d / v²)        // h = 0 时
θ = atan2(v² - √(v⁴ - g(g·d² + 2h·v²)), g·d)   // 通用
```

- 无解（`v² < g·d`）时钳到 45°。
- 炮弹每帧 `v.y -= g·dt`，位置积分；命中判定用 **球（r=0.35）vs AABB**。
- 目标 AABB：坦克 `[±2.0, 1.3±1.3, ±4.4]`，基地 `[±17, 0..6, 153..183]`。
- 落地（`y ≤ 0.12`）或 `life` 耗尽销毁；`blastRadius > 0.6` 时做一次范围伤害（0.3–0.35 系数）。
- 弹药池上限 48 发，超出丢弃最旧的。

> 数值校验：`launchSpeed 35 m/s` 打 60 m 目标，`θ = ½·asin(9.8·60/1225) = ½·asin(0.48) ≈ 14.4°`，飞行约 1.8 s。这个手感偏「慢炮」，如果觉得拖沓，把 `PROJECTILES.shell.launchSpeed` 提到 60–80（只改 `catalog.mjs` 一个数，会同时影响评估面板显示）。

### 4.5 伤害与死亡

```
实际伤害 = damageAfterDefense(attack, 目标 defense)
```

- 复用 `js/mode/campaign.mjs` 的公式，**不要另写一套**。
- 敌坦 `defense` 取模板评估值；基地 `defense = 12`。
- 血量归零 → 该单位 `alive = false`、`object.visible = false`、生成残骸（`faction: 'wreck'` + 烟柱）→ 发事件。
- 玩家阵亡发 `player-destroyed`；敌坦发 `enemy-destroyed{id}`；基地发 `base-destroyed`。

### 4.6 敌人 AI（够用即可）

| 阶段 | 条件 | 行为 |
| --- | --- | --- |
| 待机 | 玩家 z < `triggerZ` 且距离 > 26 m | 不动，炮塔朝 +Z |
| 接敌 | 触发 | 车体转向玩家；保持 22 m 间距推进 |
| 开火 | 夹角 < 0.16 rad 且距离 < 62 m 且装填完成 | 每发间隔 `1/fireRate` + 0.35–0.85 s 随机反应 |
| 守卫 | `behavior === 'guard'` | 不推进，只转车体 |

- 敌坦整辆转向（没有独立炮塔），转速用 `turnSpeed × 1.35` 让它们看起来更积极。
- **不做**寻路、躲掩体、协同——第一关 4 辆敌坦不需要。

### 4.7 相机

- 战斗开始时 `controls.enabled = false`，相机改为**第三人称跟随**：
  `camera = tank + (-sin(yaw)·12.5, 6.2, -cos(yaw)·12.5)`，位置和 `controls.target` 都用 `damp` 平滑（λ=4.5 / 6）。
- 炮塔独立瞄准，所以相机跟**车体朝向**，不跟鼠标——否则瞄准时画面会晃。
- 战斗结束/撤退时恢复 `controls.enabled = true`，并把 `controls.target` 留在坦克附近。
- **注意**：现有探针会检查 `info().target[2]` 在「准备第一关」阶段等于 82 / 8，这些检查发生在 `ready` 状态，不能受战斗相机影响。

### 4.8 与现有状态机的接法

```
准备第一关 → run.status = 'ready'，场景是静态布景（保持现状，探针依赖）
点「开战」 → transitionRun(run, {type:'start'}) → status 'running'
         → 用 combat: true 重建场景（只此一次）
战斗中     → combat 发事件 → handleCombatEvent → transitionRun → 更新面板
         → 绝不重建场景（否则战斗被重置）
结束       → status 变 victory/defeat → 停战斗、解锁 controls、重建一次静态场景展示残骸
```

**必须加的保护**：`syncLevelScene()` 在 `combat?.state.active` 时只能刷新 HUD，不能重建。

## 5. 拼装手感

### 5.1 现状的三个根因

| 根因 | 位置 | 表现 |
| --- | --- | --- |
| 松手重建整棵模型 | `applyDrag()` → `showTankScene()` → `buildTankModel` + `mergePart` × 5 | 掉落瞬间 1 帧卡顿 + 选中框闪一下 |
| 拖动中按 0.1 m 跳格 | `build-interaction.mjs` 的 `snapValue(...)` 在 `onPointerMove` 里 | 鼠标平滑移动，部件一格一格跳 |
| 没有预览 | 只有松手后的 `notify()` 文本 | 不知道会连到谁、会不会重叠 |

### 5.2 改法（按性价比排序）

**① 拖动自由、松手吸附（必做，收益最大）**
- `onPointerMove` 里去掉 `snapValue`，直接跟手。
- `endDrag` 时：在落点 1.2 m 内找最近的**可连接父件**（用现有 `moveCandidate`），把部件用 120 ms 缓动补到吸附位；没有候选才回落到 0.1 m 网格。
- 吸附完成后才 `applyDrag` 提交并重建。

**② ghost 预览（必做）**
- 拖动时显示一个半透明副本（克隆部件组，`material.transparent = true, opacity = 0.45`），位置 = 当前吸附候选。
- 同时高亮父件：复用 `createSelectionMarker` 的线框，套在父件包围盒上。
- 合法性三色：绿（合法）/ 琥珀（会重叠）/ 红（穿地或超界）。判定直接调 `validateBlueprint` 的局部逻辑，不要重复实现。

**③ 拖动中旋转（低成本，手感提升明显）**
- 滚轮 = ±15°，Shift+滚轮 = ±5°。
- 旋转时同步更新 ghost 与吸附候选。

**④ 悬停高亮**
- `onHover` 已有回调，但目前只改 footer 文案。改成给悬停部件套一个 `EdgesGeometry` 线框（复用 marker，换个颜色），并在光标旁显示部件名。

**⑤ 拖动平面**
- 现在是「水平面拖动 + Shift 切垂直」。保留，但把 Shift 的提示做成 HUD 常驻小字，并在拖动中实时显示当前 Y 值。

**⑥ 撤销粒度**
- `dragSnapshot` 已在拖动开始时压栈，保持；把「吸附 → 重新连接」并入同一次 `applyDrag`，不要拆成两次历史。

### 5.3 验收

- [ ] 拖动过程无跳格，鼠标与部件位移 1:1。
- [ ] 松手到吸附完成 ≤ 150 ms，且只有一次模型重建。
- [ ] 拖动中能看到落点预览与合法性颜色。
- [ ] 滚轮可旋转，角度以 5°/15° 步进。
- [ ] 一次拖动 = 一次撤销。
- [ ] 拖动 100 次不产生可见内存增长（`renderer.info.memory.geometries` 稳定）。

## 9. 风险与回滚

| 风险 | 触发条件 | 缓解 |
| --- | --- | --- |
| 战斗帧率不足 | 5 辆全 `merged` | 敌坦保持 `whole`；弹丸/爆炸用池化；`fixedUpdate` 里只做数学 |
| 相机与 OrbitControls 打架 | 战斗结束没恢复 `enabled` | `endCombat()` 里统一恢复；探针加断言 |
| 场景被误重建导致战斗重置 | `syncLevelScene` 没加保护 | 已在 4.8 写明；加单测断言 `combat.state.active` 时不重建 |
| 旧存档不兼容 | 新增 `map.cover` | `generateLevel()` 补默认值；`schemaVersion` 不变 |
| 探针失效 | 页签/按钮改名 | 保留所有 `data-action` 与 id；只改布局不改选择器 |

**回滚**：战斗层是**新文件 + 一处装配开关**，删掉 `combat.mjs` 并去掉 `combat: true` 即可回到纯布景；`js/mode/` 完全没动，数据与存档零风险。
