# 新模式后续工作

本文件记录后续阶段事项。模型分类导入/预览、车间部件编辑与评估、解锁、制造入库、3D 搭建交互、第一关布景与自由镜头已接入；以下对应条目继续完善到正式玩法，尚未运行真实战斗。

## 已完成（2026-11-14）

- 部件目录、自动放置、3D 点选/拖动/网格吸附、自动重新连接、撤销重做、复制/删除/旋转/升降、快捷键和自动保存。
- 程序化写实坦克代理：倾斜车体、炮塔、火炮、履带/路轮、引擎舱、附加装甲、随车附件；玩家/敌坦/守卫/残骸配色。
- 第一关场景：地形、道路、路障、沙袋、瞭望塔、基地、旗帜/雷达动画、触发线、标签、残骸与烟尘。
- 自由镜头：环绕、俯仰、平移、缩放、自动环绕、取景预设（玩家/全景/基地/敌坦）和关卡内 WASD。
- 炮塔部件与炮塔转向评估；无炮塔蓝图仍可用。
- 评估报告增加炮塔转向、尺寸和武器数量；旧草稿保持兼容。

## 下一阶段：让车间更接近正式编辑器

- 连接插槽与凸体碰撞，替代当前旋转包围盒近似；斜面装甲不再被保守误判。
- 部件高亮错误来源（断开/碰撞/失稳分别着色），并支持在报告中点击定位。
- 网格/插槽吸附的视觉提示（幽灵件、连接点、对齐辅助线）；目前只有选中框和落点吸附。
- 部件缩放、俯仰/侧倾与蓝图版本迁移；当前明确拒绝缩放。
- 撤销重做的分组（一次拖动/一次输入为一步），以及草稿多版本对比。
- 模型分类导入后的重命名、删除引用检查、存档导出备份与容量提示。
- 把真实部件 GLB 与 catalog 中的部件语义、尺寸、质量、连接插槽绑定。
- 零件解锁 UI 的经济平衡，以及新旧模式钱包是否共享的决定。

## 第一关可玩验证

- 单机输入、移动转向、炮塔瞄准，再接固定步模拟；当前场景只有静态布景和镜头。
- 碰撞代理、炮口位置、遮挡检查；装甲与生命结算。
- 子弹/炸弹/迫击炮独立弹道，明确迫击炮落点和命中延迟如何求解。
- 敌人按进度触发正面/侧袭/守卫；确保不会因未激活敌人导致软锁。
- 基地可受伤但无主动效果；胜败、重试与返回关卡选择。
- 确定同一模拟步内基地、末敌与玩家同时销毁时的结果优先级。
- 关卡编辑器：把 `level-scene.mjs` 的确定性布景替换为数据驱动的关卡资产与摆放。
- 配置真实模型，测量目标设备上的帧时间、显存、碰撞和 AI 开销，再决定实例化、LOD、对象池和 Worker。

## 评估算法后续

- 加入承重、供能、扭矩、射界、炮口遮挡、结构可靠性与部位受损。
- 重坦的硬部件与体型评价、刺坦的小型化收益、奇坦的多武器协同、高坦的射程/弹道与暴露风险。
- 通过实战样本调整类型系数和权重，避免只堆装甲或堆武器成为唯一解。
- 任意用户网格接入前设计语义标注；禁止把网格面数当作强度。
- 规则版本变化的存档迁移与旧成品提示。

## 更远的方向

- 第二关及后续关卡、分支路线、闯关地图与剧情。
- 零件奖励、成就、长期解锁和部件目录扩展。
- 联机合作对抗 AI、组队对抗、队伍与友伤规则。
- 联机权威模拟、输入命令、状态同步、重连和战局快照；不直接复用旧小游戏的对象结构。
- 服务端按蓝图重算数值，避免接受客户端伪造评估报告。

## 当前暂定、正式实现前需要确认的产品决定

1. “搭建仓库”按“搭建坦克并存入仓库”理解；是否还需要可搭建的仓库建筑？
2. 部件解锁后可重复使用，制造暂不消耗零件；是否需要单件库存或制造成本？
3. 新旧模式零件是否共用？目前分开，不迁移旧进度。
4. 第一关守卫暂定为重坦，途中三辆暂定步坦；实际难度和奖励待试玩。
5. 模型自由度先采用固定部件拼装；任意拉伸、网格雕刻和自定义材质编辑是否进入长期范围？
6. 目标设备、同屏单位规模和最低性能要求，需在大规模战斗开发前确定。
