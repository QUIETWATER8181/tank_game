# 坦克 3D 模型精致化交接文档

> 适用对象：接手「把当前程序化坦克代理升级到可发布级精致模型」的开发者，或使用 DeepSeek / 大模型辅助建模的下一轮会话。
> 记录时间：2026-11-14。当前 3D 模式（`mode3d.html`）已能搭建、预览、进入第一关布景；模型仍是程序化代理，不是最终美术资产。
> 本文只描述现状、契约、路线和验收方法；真正动手时按第 11 节里程碑推进。
>
> **进度（2026-11-14 第二轮）**：M1（比例与剪影）和 M2（近景细节）已落地，单辆唯一三角形 5,820 → 10,460，贴地误差修正到 3 mm，炮塔尾篮不再插进动力舱。实测数据见 1.3，遗留问题见 1.4，M3（贴图）之后未做。

## 0. 一分钟结论

- **现在有什么**：`js/three/tank-model.mjs` 用 Three.js 几何体按部件尺寸程序化生成整车，包含 65° 倾斜首上 + 附加装甲 + 铆钉、分段翼子板与侧裙、双轮缘负重轮 + 摆臂/减震器、带齿主动轮与诱导轮、三层收分炮塔 + 防盾 + 帆布罩 + 指挥塔 + 烟幕发射器 + 尾篮、锥度炮管 + 抽烟装置 + 炮口制退器、动力舱格栅与排气、工具箱/备用履带/拖缆/把手/焊缝等；玩家/敌坦/守卫/残骸四套配色；单辆约 **10,460 三角形 / 11 个材质槽 / 11 次绘制**（整辆合并后）。
- **缺什么**：贴图与迷彩/编号/掉漆（M3）、炮塔/履带/悬挂动画与 LOD（M4）、以及「GLB 资产 → 部件语义」的接入管线（M5）。
- **推荐路线**：M3 先用程序化图集（CanvasTexture 或预生成 PNG）把材质槽压到 ≤3，再考虑 Blender + bpy 脚本产出 PBR GLB；不要一上来做整车高模再硬塞进现有蓝图。
- **不要动**：`js/mode/` 的数据契约（部件尺寸、评估、存档）、部件组 `userData` 约定、`disposeObject` 的资源所有权、离线构建/发布包同步。模型只是表现层，不能成为数值来源。

### 1.2 当前模型做了什么（部件级）

- **车体 `hull`**：7 折点侧面轮廓挤出（65° 首上、尾部动力舱段、后倾尾板）、首上附加装甲 + 两排铆钉、驾驶员舱盖 + 3 个潜望镜 + 铰链、备用履带、车灯与护框、拖钩、分段翼子板（3 段，带伸缩缝）、侧裙、履带上方工具箱与随车工具、拖缆（沿侧翼板平铺）、把手（每侧 4 个）、焊缝（侧板顶部与首上/车顶折角）、腹板（填补两条履带之间）、尾板门 + 尾灯 + 散热格栅 + 拖钩。
- **履带 `tracks`**：每侧 64 节履带板合并成一条带子、5 对双轮缘负重轮（轮毂 + 端盖 + 5 颗轮毂螺栓）、带 10 齿主动轮、诱导轮 + 张紧臂、3 个托带轮、摆臂 + 减震器、分段侧裙 + 翼子板导轨、前后挡泥板、拖曳环。
- **引擎 `engine`**：动力舱、6 条散热格栅、进气口、双排气管 + 隔热罩 + 熏黑管口、冷却风扇（8 片扇叶）、油箱盖、侧置工具箱、吊耳。
- **炮塔 `turret`**：座圈、**三层收分**的铸造炮塔壳（宽度 2.5 → 2.42 → 2.22）、楔形防盾 + 帆布罩、偏置指挥塔（舱盖 + 4 个潜望镜 + 高射机枪 + 弹箱）、装填手舱盖 + 铰链、炮长镜、左右各 4 管烟幕发射器、天线 + 鞭状天线、尾篮（横梁 + 立柱 + 底框 + 帆布卷 + 储物箱）、备用履带、侧标、吊耳。
- **武器**：`cannon`（炮尾 + 后座套 + 锥度炮管 + 抽烟装置 + 4 道热护套环 + 双室制退器 + 并列机枪）、`rapid`（四联装 + 弹鼓）、`bomb`（定向管束 + 火箭头）、`mortar`（座钣、身管、双脚架、瞄具、弹药）。
- **装甲 `armor`**：带铆钉、横向加强筋和侧面支架的附加板。
- **配色**：`player`（橄榄绿）、`enemy`（沙褐）、`guard`（深褐 + 红）、`wreck`（焦黑）；`variant` 做轻微色相/明度扰动。

### 1.4 已知不足（按优先级）

1. **贴图缺失**：迷彩、编号、掉漆、泥污、排气熏黑全部没有；表面完全靠几何与纯色材质，近景 1 m 内仍能看出「程序化」。
2. **材质槽偏多**：11 个材质 = 11 次绘制；P1 目标 ≤3，需要图集或顶点色分区。
3. **动画**：炮塔/火炮/履带/悬挂/舱盖都没有可动枢轴（当前是静态代理），炮塔旋转时尾篮会扫过动力舱。
4. **LOD**：没有分级；第一关 5 辆 12 万三角形（含阴影）仍可接受，但大规模战斗会吃紧。
5. **形状上限**：炮塔是三段挤出，前脸和防盾仍偏方；车体侧板是一整块平面，缺少冲压/铸造起伏。
6. **资产管线**：GLB 只能预览/绑定外观，关卡和搭建仍用程序化模型；「GLB → 部件语义」尚未实现。
7. **视觉验证**：见 10.4。本轮用白色剪影 + 分部地图 + 数值审计（部件包围盒、穿模、贴地、三角形预算、悬空件）代替肉眼评审；无法判断颜色层次与材质质感，M3 之后必须有能读图的评审。

## 2. 目标与验收

### 2.1 视觉目标（三档，建议按档推进）

| 档位 | 用途 | 目标 | 参考标准 |
| --- | --- | --- | --- |
| P0 原型（现状） | 搭建/规则验证 | 一眼是坦克，部件可分辨 | 当前代理 |
| P1 近景可看 | 车间/车库/第一关特写 | 3～5 m 距离下轮廓、主要结构、材质分区可信；有迷彩/编号/轻微旧化 | 独立游戏「坦克维修/组装」类近景 |
| P2 发布级 | 宣传图/近景过场 | 焊缝、螺栓、帆布褶皱、履带节、油污/掉漆、法线细节；可做炮塔/履带/悬挂动画 | 商业坦克模拟的近景资产 |

### 2.2 工程目标

- 单辆 LOD0：**≤ 12 次绘制、≤ 80k 三角形、≤ 3 个材质、≤ 2 张 2K 贴图**（近景）；战场 LOD1 ≤ 20k、LOD2 ≤ 5k。
- 5 辆同屏 + 布景：**≤ 350 次绘制、≤ 400k 三角形**（含阴影），在目标设备 1080p 下 ≥ 50 FPS。
- 资源必须能被 `disposeObject` 正确释放；不得跨场景共享未计数的材质/贴图。
- 离线可用：不引入 CDN、不依赖运行时解码器（Draco/Meshopt/KTX2 当前不支持）。

### 2.3 本阶段明确不做

- 不做整车高模直接替换（会破坏部件搭建、评估和存档）。
- 不做任意用户网格的语义识别（面数不能当强度）。
- 不做物理/弹道/伤害；模型只负责外观与可动枢轴。
- 不改 `js/mode/` 的数值规则，除非同步升级规则版本和存档迁移。

## 3. 硬约束（不可破坏的契约）

1. **尺寸唯一来源**：`PARTS[partId].size = [宽 X, 高 Y, 长 Z]`，单位米，Y 朝上，+Z 向前。模型可以超出包围盒（炮管、天线），但**碰撞/评估/选中框以包围盒为准**。
2. **部件组约定**：每个部件是一个 `THREE.Group`，`userData = { partId, partRole, partName, partSize }`，`position`/`rotation.y` 与蓝图实例一致。选中框、拖拽、合并都依赖它。
3. **资源所有权**：每个场景根节点独立拥有几何/材质/贴图；`disposeObject(root)` 会对同一根节点内的共享资源去重释放。不要跨根节点复用材质而不做引用计数。
4. **合并**：`merged: true` 按部件合并（保留点选），`whole: true` 整辆按材质合并（清空 `userData.parts`，第一关用）。合并前所有几何统一为非索引、只保留 `position/normal/uv`。
5. **离线构建**：`npm run build:3d` 生成 `scene.bundle.js` / `core.bundle.js`，并同步到 `发布包/`；运行时不需要 npm/CDN/外网。
6. **数据兼容**：蓝图 `schemaVersion = 1`，规则版本 `prototype-2`；旧草稿（无炮塔）必须继续可用。
7. **测试门槛**：`npm run test:3d`（23 项）和三个浏览器探针必须保持通过；新增模型要补尺寸/剪影/资源释放断言。

## 4. 三条路线（决策树）

```text
需要多精致？
├─ 只要「一眼像坦克、近景不穿帮」 → A. 继续程序化（当前文件内迭代）
├─ 要迷彩/掉漆/焊缝/编号/法线细节 → B. Blender + bpy 脚本 → GLB（推荐）
└─ 已有 DCC/美术资产，要做多辆车 → C. 外部资产 + 语义标注 + LOD 管线
```

| 维度 | A 程序化 | B Blender→GLB | C 外部资产管线 |
| --- | --- | --- | --- |
| 上手成本 | 最低（改 `tank-model.mjs`） | 中（装 Blender，写/跑脚本） | 高（DCC、导出规范、映射工具） |
| 视觉上限 | 中（几何 + 程序化材质） | 高（PBR、法线、AO、贴图） | 最高 |
| 与现有搭建兼容 | 原生兼容 | 需要「部件 GLB + 语义映射」 | 同 B，另需 LOD/流式加载 |
| 运行时风险 | 低 | 中（贴图内存、加载异步） | 高 |
| 推荐用途 | P0/P1 过渡、快速验证比例 | P1/P2 主力 | 多关卡/多车型量产 |

**建议组合**：先用 A 把比例和剪影调到位（M1/M2），同时用 B 做 1 辆「样板车」验证资产管线（M3）；样板通过后再批量（M4）。C 只在确定要做多辆车/多关卡时再上。

## 5. 坦克解剖与逐部件建模指南

### 5.1 参考尺寸（与当前 catalog 对齐）

| 部件 | 当前尺寸 (X×Y×Z, m) | 真实参考（中型 MBT） | 备注 |
| --- | --- | --- | --- |
| 车体 hull | 3.4 × 1.2 × 6.4 | 3.3～3.7 × 1.1～1.4 × 6.5～7.5 | 首上倾角 60～68°（相对水平） |
| 履带 tracks | 3.9 × 0.8 × 6.6 | 履带全宽 3.3～3.8，接地长 4.5～5.5 | 单侧履带宽 0.55～0.65 |
| 引擎 engine | 1.4 × 0.8 × 1.6 | 动力舱占后部 1/4～1/3 | 排气口朝后/上 |
| 炮塔 turret | 2.5 × 0.9 × 3.4 | 宽 2.2～2.8，长 3.2～4.2 | 座圈直径 ≈ 2.0～2.4 |
| 基础火炮 cannon | 1.0 × 0.8 × 2.0 | 炮管长 4～6 m（含制退器） | 模型可超出包围盒 |
| 迫击炮 mortar | 1.4 × 1.0 × 1.8 | 身管 1.5～2.5 m | 高仰角 |
| 硬装甲板 armor | 3.0 × 1.0 × 0.35 | 附加板 20～80 mm | 竖直板，可旋转 90° 当侧裙 |
| 速射炮 rapid | 0.8 × 0.8 × 2.0 | 多管 20～35 mm | 四联装 |
| 爆破发射器 bomb | 1.2 × 0.8 × 2.0 | 定向管束/火箭巢 | — |

> 改尺寸会同时影响评估（转向、支撑、稳定性）和自动放置候选。改 `catalog.mjs` 后必须跑 `npm run test:3d`，并检查起始蓝图、装甲默认位置和 `placement.mjs` 的候选。

### 5.2 车体

- **轮廓**：真实车体不是简单楔形。建议用 5～7 个折点的侧面轮廓（挤出），再加首上/首下折角、侧裙分段、尾部动力舱段。
- **首上**：60～68° 倾角；附加装甲板要贴合斜面（当前用旋转盒 + 法线偏移），螺栓沿斜面均匀分布。
- **侧面**：翼子板、侧裙、工具箱、备品、拖缆、备用履带；注意侧裙不要穿进履带。
- **后部**：动力舱格栅、排气、拖钩、尾灯、涉水挡板。
- **细节密度**：近景每平方米 3～8 个可见细节（螺栓/把手/焊缝/管线），不要均匀撒，集中在首上、炮塔座圈、尾舱。
- **常见错误**：车体与履带同高导致重叠；首上板浮空；侧裙穿模；法线反向（挤出轮廓的绕序）；地面穿插。

### 5.3 炮塔

- **形状**：铸造炮塔用「多段轮廓 + 圆角」近似；焊接炮塔用「斜面 + 折角」。当前用挤出轮廓 + 倒角，可再加一圈侧向斜面。
- **防盾**：炮塔前脸要有防盾/帆布罩，炮管从防盾中心穿出；防盾与炮塔之间留 1～2 cm 缝，避免 z-fighting。
- **指挥塔**：偏心布置（车长侧），带舱盖、潜望镜、高射机枪；机枪要有枪架和弹箱。
- **尾部**：尾篮（栏杆 + 网/帆布卷）、烟幕发射器（4～8 管，朝前上方）、天线（2～3 根，细圆柱 + 弹簧座）。
- **细节**：吊耳、焊缝、编号、侧标、备用履带、伪装网卷。
- **常见错误**：炮塔与车体/引擎舱穿模；炮塔座圈悬空；炮管与防盾不同轴。

### 5.4 火炮

- **分段**：防盾 → 后座套 → 炮管 → 抽烟装置 → 炮口制退器。真实炮管有锥度，不要一根等粗圆柱。
- **炮口制退器**：双室/多室，侧面开槽；用 3～5 个盒体组合。
- **并列机枪**：细管 + 枪口，位置在防盾右侧。
- **炮管长度**：从防盾到炮口 3.5～5.5 m；当前模型 4.1 m 炮管 + 制退器，视觉上略长但可接受。
- **常见错误**：炮管穿进炮塔内部太多；制退器比例过大；炮管与炮塔不同轴。

### 5.5 履带与行走机构

- **履带节距**：真实 15～20 cm；当前每侧 64 节（节距约 19 cm）、带宽 0.52 m。近景建议用「一条带 + 法线/位移贴图」或 InstancedMesh，不要 100+ 独立网格。
- **负重轮**：5～6 对，直径 0.6～0.75 m；带橡胶轮缘 + 金属轮毂 + 螺栓。
- **主动轮**：后置或前置（按车型），带齿；诱导轮带张紧机构；托带轮 3 个。
- **悬挂**：扭杆/油气悬挂的摆臂、减震器；静态模型也要有摆臂，别让轮子悬空。
- **常见错误**：履带不闭合；轮子悬空/入地；履带与车体侧裙穿模；左右不对称。

### 5.6 引擎/动力舱

- 格栅（散热片）、进气口、排气歧管 + 隔热罩、风扇、油箱盖、工具箱。
- 排气口要朝后/上，避免正对乘员舱；可加轻微黑烟贴图/粒子（表现层）。
- 近景可加管线、卡箍、铭牌。

### 5.7 附加装甲

- 竖直板（当前 `armor` 是 3 × 1 × 0.35），可 yaw 90° 当侧裙；加铆钉、加强筋、支架。
- 真实附加装甲有间隙（standoff），不要完全贴死；留 2～5 cm 缝并用支架连接。
- 注意别挡住炮塔旋转路径和驾驶员视野。

### 5.8 附件与「故事感」

工具箱、拖缆（盘绕/下垂）、备用履带、伪装网卷、帆布、水桶、天线、编号、部队徽标、泥污/掉漆。**附件是近景可信度的关键**，但不要影响碰撞盒和性能。

### 5.9 常见错误清单

- 比例：炮塔过大/过小、炮管过粗、履带过窄。
- 穿插：炮塔/引擎舱、侧裙/履带、附件/车体。
- 法线：挤出轮廓绕序反了导致内表面发黑；合并后法线不一致。
- 悬空：轮子/挡泥板/拖钩没有接触点。
- 重复：同一细节均匀铺满，缺少主次。
- 性能：每个螺栓一个 mesh、每个轮子一个材质、贴图未图集化。

## 6. 材质与贴图

### 6.1 PBR 参数建议

| 材质 | 颜色 | metalness | roughness | 备注 |
| --- | --- | --- | --- | --- |
| 车体漆面 | 橄榄绿/沙褐/深褐 | 0.15～0.3 | 0.55～0.75 | 迷彩用贴图或顶点色分区 |
| 裸露金属 | 深灰 | 0.7～0.9 | 0.25～0.45 | 炮管、履带、工具 |
| 橡胶 | 近黑 | 0.0～0.05 | 0.85～0.95 | 轮缘、挡泥皮 |
| 玻璃/潜望镜 | 深蓝黑 | 0.8 | 0.1～0.2 | 可加轻微自发光 |
| 帆布 | 卡其 | 0.0 | 0.9 | 防盾罩、炮衣、网卷 |
| 锈/油污 | 棕/黑 | 0.2～0.4 | 0.8～1.0 | 用贴图叠加，别整块换色 |

- 颜色空间：贴图 `SRGBColorSpace`；法线/粗糙度/AO 用线性。
- 当前渲染器：ACES Filmic + 曝光 1.18（车间）/0.95（关卡）；新增材质要在两套曝光下都检查，避免过暗/过曝。
- 环境光照：`RoomEnvironment` PMREM，`environmentIntensity` 车间 0.5 / 关卡 0.6；金属度高的部件依赖环境反射，别把 metalness 拉到 1。

### 6.2 贴图规格

- 近景：2048² 图集（albedo + normal + roughness/metalness + AO），单辆 ≤ 2 张；战场：1024² 或 LOD 专用。
- 图集布局：车体/炮塔/履带/附件各占一块；UV 不重叠；留 4～8 px 边距防渗色。
- 迷彩：三色/四色硬边迷彩；掉漆露出底漆/金属；履带和轮缘加泥污；排气口加黑烟熏。
- 编号/徽标：单独小贴图或图集区块，避免每辆车一张大图。
- 无贴图降级：用顶点色/材质分区 + 程序化噪声（`CanvasTexture`）也能明显提升；注意 CanvasTexture 在无 DOM 环境（Node 测试）要跳过。

### 6.3 性能注意

- 材质数直接决定绘制次数：单辆 ≤ 3 个材质（车体/金属/橡胶），把玻璃、灯、锈合并进图集或顶点色。
- 贴图内存：2048² RGBA ≈ 16 MB/张（含 mip）；5 辆同屏不要每辆独立大图，尽量共享图集。
- 法线贴图会增加片元成本，低端设备用 LOD1 关闭。

## 7. 层级、枢轴与动画

### 7.1 节点命名（与现有约定一致）

```text
Tank (root)
├─ Hull
│  ├─ HullBody
│  ├─ Fender_L / Fender_R
│  └─ ...
├─ Turret (pivot = 炮塔座圈中心)
│  ├─ TurretBody
│  ├─ Mantlet
│  ├─ Cupola
│  ├─ Barrel (pivot = 防盾中心)
│  │  └─ Muzzle (空节点，炮口位置)
│  └─ ...
├─ Track_L / Track_R
├─ Wheel_L_01 ... Wheel_R_05
└─ ...
```

- 当前程序化模型的部件组名是蓝图实例 id（`hull`/`turret`/`weapon`…），**不要直接改名**；若要加动画枢轴，在部件组内部再加子组（如 `turret.userData.pivot` 或子节点 `TurretPivot`）。
- glTF 导出：+Y up、+Z forward；导出后以 glTF 为准再核对一次轴向（不同 DCC 的 forward 设置不同）。
- 枢轴：炮塔座圈在车体顶面中心；炮管枢轴在防盾中心；轮子在轮心；舱盖在铰链边。

### 7.2 动画建议

- 炮塔 yaw：`Turret.rotation.y`，范围 ±180°；炮管 pitch：`Barrel.rotation.x`，-8°～+20°。
- 履带：UV 偏移（贴图）或 InstancedMesh 位移；不要逐节骨骼。
- 悬挂：轮子上下 + 摆臂旋转；静态模型可只做摆臂角度。
- 舱盖/天线/旗帜：轻微摆动即可。
- 命名建议：`TurretYaw`、`BarrelPitch`、`TrackScroll`、`HatchOpen`；循环动画标记 `loop`。

### 7.3 与当前静态代理的差异

当前 `buildTankModel` 返回的是**静态**部件组；炮塔/火炮没有独立枢轴。若要做动画，建议在 `tank-model.mjs` 内部给炮塔/武器组加子枢轴，或在 GLB 资产里直接带层级，再在表现层读取节点。注意：**炮塔旋转时武器要跟随**，而当前蓝图里武器的位置/朝向是绝对坐标，需要表现层做「相对炮塔」的换算（数据层不改）。

## 8. 与现有代码的接入

### 8.1 `buildTankModel` 契约

```js
buildTankModel(blueprint, {
  faction = 'player',   // player | enemy | guard | wreck
  variant = 0,          // 配色扰动
  merged = false,       // 按部件合并（保留点选）
  whole = false         // 整辆按材质合并（关卡用，清空 parts）
})
```

- 返回 `THREE.Group`，`userData = { parts: Map<partId, Group>, byRole: Map<role, Group>, materials, faction }`；`whole` 时 `parts/byRole` 为空。
- 每个部件组必须有 `partId / partRole / partName / partSize`，位置/朝向与蓝图实例一致。
- 新增部件类型时，在 `BUILDERS` 里注册 `role -> builder`；武器按 `partId` 分派。构建器签名 `(group, materials, { part, item, blueprint })`，只往 `group` 里加 mesh，不要改蓝图。
- 几何工具：`box`、`cylinder`、`mesh`、`profile`（侧面轮廓挤出，points 为 `[z, y]`，沿 X 挤出宽度，带倒角）。合并工具：`mergePart`、`mergeWhole`、`collectMerged`、`addMerged`。

### 8.2 若改用 GLB 资产（推荐 M3 方案）

当前缺口：`assets.mjs` 只做「整车预览」，`level-scene.mjs` 不读取 `tank.modelId`。要接入精致模型，建议新增（不改现有数据契约）：

1. **部件资产表**：`{ partId, assetId, pivot: [x,y,z], scale, rotation }`，存 IndexedDB 或 JSON。
2. **异步加载器**：`GLTFLoader` 按 assetId 加载并缓存；`buildTankModel` 改成 async 或在场景装配前预加载。
3. **装配规则**：按蓝图实例的 `position/yaw` 放置部件 GLB；炮塔/炮管使用资产内枢轴；`userData.partSize` 仍取 catalog 尺寸（选中框/拖拽不变）。
4. **回退**：资产缺失/加载失败时回退到程序化构建器，不能阻断搭建。
5. **释放**：每个装配根节点独立克隆材质/贴图（或引用计数），`disposeObject` 才能安全释放。

### 8.3 选中/拖拽/评估不受影响的前提

- 部件组位置 = 蓝图 `position`，`rotation.y` = `yaw`；选中框用 `partSize` 计算（不依赖网格包围盒）。
- 不要给部件组加缩放/父级偏移；需要偏移时放在部件组内部的子组。
- 合并只影响渲染，不影响部件组（`merged` 模式保留组；`whole` 模式用于关卡，不参与编辑）。
- 评估仍用 catalog 包围盒，模型细节（炮管/天线）不参与碰撞。

| 场景 | 绘制次数 | 三角形（唯一） | 材质 | 贴图 | 备注 |

## 10. 用 DS / 大模型做精致模型的工作流

> 网上「用 DS 做 3D 建模」常见两条路：**让模型写 Three.js 程序化几何**，或**让模型写 Blender bpy 脚本生成 GLB**。两条都能用，关键是「规格先行 + 小步验收」，不要一次让模型生成整车。

### 10.1 先写规格，再写代码

在提示词里给出**可验证的规格**，而不是「画一辆真实坦克」：

```text
目标：在现有 tank-model.mjs 的 buildHull 中增加首上折角与侧裙分段。
约束：
- 车体包围盒 3.4 × 1.2 × 6.4，Y 朝上，+Z 向前；
- 只使用 THREE.BoxGeometry / CylinderGeometry / ExtrudeGeometry；
- 不新增材质，使用 mats.hull / mats.hullDark / mats.metal；
- 新增几何总三角形 ≤ 1500；
- 不得改变部件组 position/rotation 与 userData；
- 给出每段几何的尺寸和位置表。
验收：npm run test:3d 通过；三视图剪影仍满足 width 3.4～5.5 / length 7～10 / height 2.5～5.2。
```

### 10.2 提示词模板

**A. 程序化几何（Three.js）**

```text
你是 Three.js 几何工程师。现有函数 buildTurret(group, mats, ctx) 生成炮塔。
请在不改变部件组契约的前提下，把炮塔前脸改成「倾斜 + 圆角」：
1) 先列出 5～8 个折点的 (z,y) 侧面轮廓；
2) 用 ExtrudeGeometry 沿 X 挤出 2.5 m，倒角 0.05；
3) 增加防盾、炮塔尾篮、4 个烟幕发射器，给出尺寸/位置；
4) 总三角形 ≤ 2500，材质只用 mats.hull/hullDark/metal；
5) 输出完整函数，不要省略号，不要引入新依赖。
```

**B. Blender bpy 脚本 → GLB**

```text
你是 Blender Python 工程师（Blender 4.x）。请生成一个 bpy 脚本：
- 建立炮塔低模（≤ 8k 三角形），原点在炮塔座圈中心，+Z 朝前，+Y 朝上；
- 材质：PBR，1 张 2K 图集（albedo/normal/roughness-metallic/AO）；
- 命名：Turret / Mantlet / Barrel / Muzzle，Barrel 的枢轴在防盾中心；
- 导出 glTF 2.0 GLB（内嵌贴图，不压缩，+Y up）；
- 脚本可直接在 blender --background --python 下运行；
- 输出前打印每个对象的三角形数和包围盒。
```

**C. 材质/贴图**

```text
为低模坦克生成 2048² PBR 图集：三色硬边迷彩（橄榄/深绿/沙褐）、
掉漆露金属、履带泥污、排气口黑烟、白色战术编号。
要求：UV 不重叠、留 8px 边距、颜色空间 sRGB、法线/粗糙度线性；
给出图集分区坐标表。
```

**D. 排错**

```text
现象：合并后模型发黑/部分面消失。
请按以下顺序排查并给出最小修复：
1) 挤出轮廓绕序；2) 法线是否反向；3) 合并前是否统一为非索引；
4) 材质 side 是否 FrontSide；5) 是否有零面积三角形。
只改必要代码，并给出验证命令。
```

### 10.3 迭代循环（每次只做一个小目标）

1. 写规格（尺寸表 + 预算 + 验收）。
2. 让模型生成**一个函数/一个部件**，不要整车。
3. 本地构建：`npm run build:3d`；单测：`npm run test:3d`。
4. 截图：`node tools/pseudo3d/shoot.js --page=mode3d.html --out=...`。
5. 三视图剪影 / 像素统计（见 10.4），必要时让具备视觉能力的模型或人评审。
6. 通过后再做下一个部件；每步一个 commit，方便回滚。

### 10.4 验证闭环（不能读图时按这个来）

本轮新增了两个可复用工具，把「截图 → 剪影 → 数值」串成一条命令：

- `tools/pseudo3d/tank-views.js`：`shoot.js --afterFile` 钩子。隐藏页面 UI、把视口铺满、关掉地板/网格/雾、把整车涂成纯白自发光、按包围盒自动取景，并返回三角形/网格/材质/各部件包围盒等 JSON。
- `tools/pseudo3d/silhouette.py`：把任意截图打成 ASCII 剪影 + 亮度统计。
- `tools/pseudo3d/part-map.py`：把多张「单部件剪影」叠成一张部件地图（字母 = 部件），用来检查布局与穿插。

```powershell
# 侧视整辆剪影（返回的 JSON 里有三角形/包围盒/部件数据）
node tools/pseudo3d/shoot.js --page=mode3d.html --query=view=side `
  --afterFile=tools/pseudo3d/tank-views.js --afterWait=1200 `
  --evalFile=tools/pseudo3d/tank-views.js --out=tools/pseudo3d/shots/side.png
$py = "C:\Users\tiann\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe"
& $py tools/pseudo3d/silhouette.py tools/pseudo3d/shots/side.png --cols=104 --rows=64

# 分部地图：先按部件各截一张（相机锁定在整车包围盒上，所以能对齐）
foreach ($p in 'tracks','hull','engine','turret','weapon') {
  node tools/pseudo3d/shoot.js --page=mode3d.html --query="view=side&solo=$p" `
    --afterFile=tools/pseudo3d/tank-views.js --afterWait=900 --out="tools/pseudo3d/shots/side-$p.png"
}
& $py tools/pseudo3d/part-map.py --view=side `
  --part=T:tools/pseudo3d/shots/side-tracks.png --part=H:tools/pseudo3d/shots/side-hull.png `
  --part=E:tools/pseudo3d/shots/side-engine.png --part=U:tools/pseudo3d/shots/side-turret.png `
  --part=W:tools/pseudo3d/shots/side-weapon.png
```

`view` 可选 `side|front|top|three|iso`；加 `&plain=1` 保留真实材质，用来做亮度统计。

**① 剪影判读**：炮管是否伸出、炮塔是否在车体上方、履带/轮子是否贴地、首上是否够斜、侧裙是否盖住轮子、有没有孤立浮空的块。ASCII 的横竖像素比不同，读比例时用 `--rows` 对齐图片宽高比（1440×900 用 104×64），否则会看着「压扁」。

**② 数值审计**（比肉眼更可靠，脚本见 10.3 的临时脚本写法）：逐部件打印三角形、包围盒；检查
- 整车 `min.y` 是否 ≈ 0（贴地）；
- 炮塔 `min.z` 是否大于动力舱 `max.z`（尾篮不插引擎）；
- 各部件包围盒的重叠是否都是「设计意图」（炮塔座圈压车顶、炮管根部插炮塔）；
- 每个 mesh 的世界包围盒超出所属部件盒的部分是否合理（炮管/天线可以超，螺栓/把手不能飘）；
- 每个 mesh 是否至少和同部件内的另一个 mesh 相交（悬空件检测，已固化进 `tests/tank-model.test.mjs`）。

**③ 颜色/亮度统计**：`silhouette.py` 末尾会打印 mean/median/p95/亮部%/暗部%，确认没有过曝或全黑。

**④ 浏览器探针**：`tests/workbench-browser-probe.js`（搭建/拖拽/相机/第一关）、`tests/three-browser-probe.js`（导入/上下文恢复）、`tests/mode-storage-browser-probe.js`（IndexedDB）。

**⑤ 单测**：`tests/tank-model.test.mjs` 断言尺寸、剪影地标、合并、资源释放、细节预算、部件间隙与悬空件；改模型后必须全绿。

**⑥ 真机**：`?stats=1` 看 FPS/绘制/三角形；目标设备实测后再谈优化。

### 10.5 AI 常见错误清单

- **API 幻觉**：Three.js 版本 0.187.0，不要用已废弃的 `Geometry`/`THREE.Face3`；`BufferGeometryUtils` 从 `three/addons/utils/BufferGeometryUtils.js` 导入。
- **轴向/单位**：+Z 向前、Y 向上、1 单位 = 1 米；glTF 导出后要复核。
- **合并属性不一致**：索引/非索引、属性集不同会导致 `mergeGeometries` 返回 null；合并前统一为非索引并只保留 position/normal/uv。
- **资源泄漏**：每个场景根节点独立拥有资源；跨根共享要引用计数；`disposeObject` 只对同一根去重。
- **穿模/悬空**：所有附件要有接触点；炮塔/引擎舱/侧裙重点检查。
- **过度细节**：每个螺栓一个 mesh 会让绘制爆炸；用合并/实例化/贴图。
- **忽略曝光**：车间和关卡曝光不同，材质要在两套下都看。
- **改数据契约**：不要为了模型好看改 `PARTS.size` 而不跑评估/放置测试。

### 10.6 什么时候停止用 AI 生成几何

- 需要照片级焊缝/铸造纹理/布料褶皱 → 转 Blender/雕刻/贴图，AI 只写脚本和材质。
- 需要多车型/多关卡量产 → 建资产管线（路线 C），AI 写工具链而不是逐个模型。
- 性能不达标且合并/图集已做尽 → 做 LOD/实例化，而不是继续加细节。

**M1/M2 具体改了什么**（回滚时按这个顺序反做）：

1. 车体轮廓从 6 折点改成 7 折点：首上从 54° 提到 65°，尾部改成后倾尾板 + 动力舱段。
2. 首上细节全部改挂到 `slopeFrame(from, to)` 上，用 `at(x, up, along)` 定位（`up` 沿外法线，`along` 正方向朝车头），这样改倾角时铆钉/舱盖/车灯会一起跟着走，不会浮空。
3. 车灯从首上挪到翼子板前端（陡首上沿法线偏移会让灯前伸过多）。
4. 履带节距 54 → 64 节；负重轮改双轮缘 + 轮毂端盖 + 螺栓；补摆臂与减震器；`bandCenter` 从 -0.06 改到 -0.025，使履带最低点正好落在 y = 0。
5. 炮塔改成三段挤出（2.5 / 2.42 / 2.22），前脸和顶部才有收分；尾篮后移到世界 z ≈ -1.4，避开动力舱（原先是插进去 8 cm）。
6. 拖缆从「立在车顶的半圆环」（TorusGeometry 未旋转，翘起 0.5 m）改成沿侧翼板平铺的 `TubeGeometry`。
7. 补腹板（两条履带之间），否则前/后视图中间是空的。
8. 炮管改成两段锥度 + 抽烟装置 + 4 道热护套环 + 双室制退器；总长 9.76 m，仍在单测的 7～10 m 区间内。

> 坐标坑：`buildHull`/`buildTurret` 里所有位置都是**部件组局部坐标**，而部件组本身带 `position`（车体 y = 1.4、炮塔 y = 2.45）。写 `[x, 1.46, z]` 会得到世界 y = 2.86 的悬空件——本轮就是靠 10.4 的悬空件检测抓到的。

## 15. 回滚与风险

- 模型改动集中在 `js/three/tank-model.mjs`；回滚该文件即可回到当前代理，数据层不受影响。
- 若引入 GLB 管线，保留「程序化回退」开关；资产加载失败不能阻断搭建/制造/关卡。
- 改 `catalog.mjs` 尺寸会同时影响评估与放置，必须同步更新起始蓝图、装甲默认位置、`placement.mjs` 候选和测试。
- 不要删除 `partSize`/`partId` 等 `userData`；点选、拖拽、选中框、合并都依赖它。
- 发布包由 `npm run build:3d` 同步；不要手改 `发布包/` 里的 bundle。
