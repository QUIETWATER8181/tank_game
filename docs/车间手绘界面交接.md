# 车间手绘界面交接

> 记录时间：2026-11-21。适用对象：接手「把 3D 车间从开发者面板改成手绘军工档案」的开发者。
> 本文只写**现状、规格、改法与验收**，不改代码。配套：[界面检验指南](界面检验指南.md)（怎么验）、[3D 玩法与第一关交接](3D玩法与第一关交接.md)（战斗与关卡）、[3D 坦克模型精致化交接](3D坦克模型精致化交接.md)（模型层）、[新模式架构](新模式架构.md)（数据层）。

## 0. 一分钟结论

- **现在是什么样**：整页是一张手绘军工档案纸。左栏是「部件清单 / 可装部件 / 当前部件 / 备注 / 附页」，中间是一张贴着胶带的**照片**（照片里是实时 3D 视口），照片下方是一张**按蓝图实时绘制**的手绘平面布置图，右栏是「验收单」。页眉是行楷标题 + 编号日期，底部是操作行与视角工具。
- **没动什么**：`js/mode/` 一行没改。存档、评估、关卡、战斗、模型全部原样。四个浏览器探针、41 个单元测试全过。
- **最关键的三个决定**：
  1. **手绘只做在线条、字体、圈注上**，版式网格仍然是正的——不然会脏。
  2. **所有"歪线"都是 SVG 背景图 `repeat-x`**，不是固定坐标的 SVG。行数变了、列宽变了、数字重排了，线还是歪的，重绘不会错位。
  3. **3D 视口嵌进照片框**，不是截图。照片是活的：能点、能拖、能转视角。

### 2.3 三条"歪线"（`--wavy` / `--wavy-red` / `--wavy-ink`）

都是 160×6 或 60×4 的 SVG 波浪线 data URI，用 `background-repeat: repeat-x; background-position: left bottom` 铺在元素底部。

**为什么不用 `border`**：`border` 是绝对直的。**为什么不用固定坐标的 SVG 画表格**：表格行数随部件变化，一重绘就错位。背景图是唯一"随内容拉伸还保持手绘"的方案。

### 2.4 纸感

- 纸纤维：`body::after` 铺 `feTurbulence` 噪点，`mix-blend-mode: multiply`，透明度 `.5`。
- 照片：白色相纸 + 两段胶带 + 轻微旋转（`-.55deg`）+ 双层投影。
- 便签 / 印章 / 铅笔圈：见 `.guide`、`.seal`、`.circled`。

## 3. 设计决策（为什么这么干）

1. **纸，不是玻璃。** AI 味的根源是"平均"：所有元素同权重、同圆角、同亮度。纸有偏执——某处字大、某处留白、某处有咖啡环。手绘线是"人留下的误差"，这比任何配色都更能去 AI 味。
2. **照片是活的。** 主页面保留样张 A 的"照片贴纸"构图，但照片里是实时 canvas。用户既能得到"这是一张图纸/照片"的叙事，又不失去 3D 的交互。
3. **验收单是判断，不是清单。** 原来右栏 12 行"标签 + 右对齐数字"是调试器。现在默认 8 行，其中稳定性用红笔圈出，其余进「全部数值与计算依据」。
4. **制造是盖章。** 全屏唯一的红框按钮，`制造并入库` 做成印章，符合"这是要签字的"心理模型。
5. **平面布置图必须是真的。** 它按 `metrics.size`、炮塔位置、主武器尺寸实时绘制，尺寸线标真实数字。假的装饰图会被玩家一眼看穿。
6. **选中框从荧光绿改成琥珀。** 荧光绿在纸上是异物。`#e0a13a` 读起来像铅笔框。
7. **数据层零改动。** 所有玩法数值、存档、评估、战斗都不碰，UI 只是换了一层皮。

## 4. 改法细节

### 4.1 `mode3d.html`

- 删掉了旧工具栏（自由视角/自动环绕/复位/画质）和底部悬浮 dock 的固定定位。
- `#viewport` 从 `position: fixed; inset: ...` 改成嵌在 `.plate > .shot` 里，`position: absolute; inset: 0`。`SceneRuntime` 用 `ResizeObserver` 观察宿主，所以尺寸变化会自动跟上。
- 视角工具（`[data-camera]`、`#resetCamera`、`#quality`）移到页脚 `.view-tools`。**这几个是 `main.mjs` 和探针硬依赖的，不能删**。
- `#buildDock` 移进左栏 `.ops`，按钮从图标改成文字（撤销/重做/左转 15°/右转 15°/升高/降低/吸附/复制/删除）。

### 4.2 `css/mode3d.css`

- 整份重写，约 350 行。断点：`1180px` 收窄三栏；`900px` 改成单列（`display: flex` + `order`），照片排在最前、平面图隐藏。
- 表单控件统一改成"手填"样式：只有一条底线，聚焦时变红。
- `.card` / `.selection-card` 不再是有边框的盒子，而是"一条波浪线隔开的一段"。
- 滚动条做成细的纸色（`scrollbar-width: thin`）。

### 4.3 `js/three/workbench.mjs`

- **`renderReport(value, source)`**：输出验收单。合法时 8 行 + 红笔圈 + 印章 + 复核行 + 折叠的全部数值；非法时输出「需要调整」+ 错误列表，并禁用制造按钮。
- **`renderWorkshopPanel()`**：
  - 写 `#docTitle` / `#docSub`（标题 = 蓝图名 + 改装方案）。
  - 部件清单用 `.ledger` 表格，选中行状态显示「选中」（红）。
  - 「可装部件」**过滤掉已装的唯一部件**（车体/履带/引擎/炮塔），武器和装甲继续显示。
  - 「当前部件」保留复制/移除/主武器 + 精确调整折叠区（`[data-coordinate]`、`#yawOutput`、`#selectedPart`、`#partParent` 都在这里）。
  - 「附页」折叠区放蓝图名、类型、外观模型、草稿、模型仓库入口（`#blueprintName`、`#tankType`、`#boundModel`、`#savedDraft` 都在这里）。
  - 最后写 `#docFoot`（保存 / 制造 / 签字行），再 `renderReport()`，再 `renderSketch()`。
  - **顺序很重要**：`#docFoot` 必须在 `renderReport()` 之前写，否则制造按钮的 `disabled` 设不上。
- **`renderSketch(value)`**（新增）：按蓝图画俯视图。比例 `min(330/长, 128/宽)`，viewBox `0 0 600 176`，中心 `(300, 74)`。两条履带 + 车体 + 炮塔椭圆 + 炮管 + 履带齿 + 两条尺寸线，整体套 `feDisplacementMap` 抖动。
- **`render()`**：切到非车间页签时清空 `#docFoot` / `#sketch`，并隐藏引导。
- **`updateDock()`**：同时隐藏/显示外层 `.ops`，避免其它页签出现空的「操作」标题。
- **初始化**：写入 `#docDate`（当天日期）。

### 4.4 `runtime.mjs` / `build-interaction.mjs`

- 车间复位镜头：`(7.6, 6.2, 9.6)` → 目标 `(0, 1.7, 0)`（原来 `(10.5, 8.4, 13.2)`，在新照片框里坦克太小）。
- `MARKER_COLOR = '#e0a13a'`、`HOVER_COLOR = '#8fb0c8'`。

### 7.1 已修：验收单常驻「turret：部件未解锁」

- **症状**：右栏验收单常驻「需要调整」，只有一条红字 `turret：部件未解锁`，制造按钮一直禁用；每个新蓝图、每次刷新都一样。复现图见 `tools/mockups/bug-turret-locked.png`。
- **原因**：`unlockedParts` 是建库时按当时目录算的一次性快照。prototype-1 时代的目录里没有炮塔，那份存档里就没有 `turret`；炮塔后来以 `cost: 0` 加进目录，但 `newProfile()` 只在「没有存档」时执行，老存档不迁移。`createStarterBlueprint()` 的每个蓝图都带炮塔，所以每次拼装都命中；炮塔又已经装在车上，「可装部件」按设计不列已装的唯一部件，界面上连解锁入口都没有。
- **修法**：`js/mode/storage.mjs` 新增 `migrateProfile()`，读/写存档时把 `cost === 0` 但缺的部件补回 `unlockedParts`（付费部件不动）。回归测试：`tests/mode-core.test.mjs`「老存档缺免费部件时自动补回」+ `tests/mode-storage-browser-probe.js` 的 `legacy unlock migration`。
- **注意**：这是数据层的补丁，界面没动。用户刷新页面即恢复；不需要清 IndexedDB。

## 8. 回滚

本次改动是**纯表现层**，数据与玩法零风险。但工作区里有上一轮的未提交改动，**不要整文件 checkout**。

推荐做法：

```sh
# 1. 先看清哪些是本轮的改动
git diff --stat

# 2. 只回滚本轮动过的文件（注意：runtime.mjs / workbench.mjs 里也含上一轮的改动！）
#    安全做法是用 git diff 挑出本轮的 hunk 反向应用，或从本轮的提交里 revert。

# 3. 如果本轮单独提交过，直接：
git revert <本轮提交>

# 4. 无论怎么回滚，最后都要重建
npm run build:3d
```
